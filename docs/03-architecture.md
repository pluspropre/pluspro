## 3. Rendering strategy

| Route | Rendering | Data | Invalidation |
|---|---|---|---|
| `/`, `/a-propos`, `/services`, `/services/[slug]`, `/realisations` | Static (prerendered at build) + cached data reads | Static content from `src/content`; reviews, projects, latest posts from Supabase via cached functions | Tag invalidation from admin actions (`reviews`, `projects`, `posts`), time-based fallback 1 h |
| `/actualites`, `/actualites/[slug]`, `/actualites/categorie/[slug]` | Static + `generateStaticParams` for existing posts; new slugs rendered on demand then cached | Supabase | Tags `posts`, `post:{slug}`; time-based fallback ≤ 1 h so scheduled posts appear on time |
| `/devis` | Static shell, client wizard; prefill read from `searchParams` on the client (keeps the page static) | — | — |
| `/devis/merci` | Static, `noindex` | — | — |
| Legal pages | Static | `src/content/legal` | Rebuild |
| `/admin/**` | Dynamic, never cached, `noindex` | Supabase with user session (RLS as the user) | — |
| `sitemap.ts` | Cached, tag `posts` + 1 h | Supabase (published posts) | Same as blog |

### Caching implementation (Next 16)

- Enable **Cache Components** (`cacheComponents: true` in `next.config.ts`) and write public data functions with
  `'use cache'`, `cacheTag('posts')`, `cacheLife('hours')`. In admin server actions call `updateTag('posts')` (read-your-
  writes) or `revalidateTag('posts', 'max')`. If the installed Next version differs, follow its caching docs — the
  contract is: **public pages are cached and tag-invalidated by admin mutations, with ≤ 1 h time-based expiry**.
- Cached functions must use the **cookie-less** Supabase client (`lib/supabase/public.ts`, `createClient` from
  `@supabase/supabase-js` with the publishable/anon key, `auth: { persistSession: false }`). Never read cookies inside a
  cached scope.
- Public reads rely on RLS (published rows only) **and** explicit filters in the query (defence in depth).
- Scheduled posts: the query filters `status = 'published' AND published_at <= now()`. Because list pages expire
  hourly, a post scheduled for 09:00 appears by 10:00 at the latest. If the client needs minute precision, add the
  optional Vercel Cron (§5).

## 4. Data flow

```
Visitor ──► Vercel Edge/CDN ──► cached RSC page ──(cache miss)──► lib/data/* ──► Supabase (anon key, RLS: published only)

Visitor submits quote ──► server action submitQuote (zod + honeypot + Turnstile verify)
                         ├─► Supabase quote_requests (secret key, server-only)
                         ├─► Resend: notification to contact@plus-propre.fr (reply-to = prospect)
                         └─► Resend: confirmation to prospect (optional, recommended)
                         └─► redirect /devis/merci

Admin (phone/desktop) ──► /admin (proxy refreshes session) ──► (protected)/layout requireAdmin()
   ├─ uploads: browser → compress/strip EXIF → supabase.storage (user JWT, storage RLS: admins only)
   └─ save: server action → zod → supabase (user session, RLS: is_admin()) → updateTag(...) → public pages refresh
```

## 5. Optional Vercel Cron

`/api/cron/revalidate` (GET, checks `Authorization: Bearer ${CRON_SECRET}`) revalidates tag `posts` if any post's
`published_at` fell within the last interval. Note: on the Vercel **Hobby** plan crons run at most once per day.
Only add this if hourly time-based expiry is not precise enough.

## 7. Security

- **Supabase**: RLS enabled on every table; admin determined by `public.profiles.role` via a `security definer`
  function `is_admin()` (see `06`). Disable public sign-ups in Supabase Auth settings; admins are invited.
- Secret key only in `lib/supabase/admin.ts` with `import 'server-only'`. Lint rule/grep in CI to forbid importing it
  from client components.
- **Admin guard in three layers**: `src/proxy.ts` refreshes the session and redirects unauthenticated `/admin/*`
  requests to `/admin/login`; `(protected)/layout.tsx` calls `requireAdmin()` (server, `supabase.auth.getUser()` —
  never trust `getSession()` on the server); every server action calls `requireAdmin()` again. RLS is the last line.
- Server actions: zod-validate all input; return typed results; never echo raw errors to the client.
- HTML from the editor is sanitised on save **and** rendered only from the sanitised column.
- Headers (in `next.config.ts` `headers()`): `Strict-Transport-Security` (already set by Vercel), `X-Content-Type-Options:
  nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(),
  geolocation=()` (note: the admin camera capture uses a file input, which is not affected), `X-Frame-Options:
  SAMEORIGIN`. Add a Content-Security-Policy in report-only mode first (allow Supabase, Turnstile, Vercel
  insights, Google Fonts are self-hosted by `next/font` so not needed), then enforce.
- Rate limiting: Turnstile + honeypot + minimum fill time (reject submissions < 3 s after the wizard mounted). Add a
  per-email throttle in the action (max 3 requests / 10 min, checked in `quote_requests`).
- Preview deployments: `X-Robots-Tag: noindex` when `VERCEL_ENV !== 'production'` (set in `proxy.ts` or `headers()`),
  and enable Vercel Deployment Protection for previews.
